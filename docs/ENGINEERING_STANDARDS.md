# Engineering standards for this portfolio

These principles apply across the mission and future work on the owner's projects.

- Solve a clear user problem and define observable acceptance criteria.
- Trace root causes, reproduce failures, and fix recurring problems in shared code.
- Preserve each project's purpose, licensing, provenance and existing user changes.
- Use secure defaults, scoped credentials and explicit network identities. Keep keys out of code, logs and browser bundles.
- Prefer maintainable designs and supported, pinned dependencies. Verify updates before release.
- Test real behavior, failure paths, resource bounds and recovery. Keep checks proportionate to risk.
- Release immutable, reviewed commits with reproducible build and runtime evidence.
- Distinguish measured capabilities from plans, simulations and independent certification.
- Make routine engineering decisions autonomously within the authorized scope. Involve the owner for new spending, ownership, licensing or irreversible actions beyond that scope.
- Keep status candid: a passing build or a repository count does not establish customer readiness or guarantee a competition result.
